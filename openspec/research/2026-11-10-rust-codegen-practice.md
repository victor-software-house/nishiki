# Rust code generation in practice

Where do mature Rust projects run code generation, how do they write and lay out the code, and what does each choice cost?

It informs the `rust-codegen` change.

## Answer

- The projects read keep generated Rust committed in `src/`.
  A workspace tool or a `cargo xtask` regenerates it.
  CI runs the generator again and fails on `git diff`.
- Only crates a caller's `build.rs` calls write into `OUT_DIR`: `phf_codegen`, `prost-build` and `windows-bindgen`.
  None of them commits that output.
- The common writer is `proc-macro2` and `quote`, laid out by `prettyplease`.
  rustfmt is the other choice, and every library read makes it optional or best-effort.
- Plain string writers lay out numeric tables.

## Where code generation runs

1. rust-analyzer moved from `sourcegen` tests to an `xtask` command.
   - [`xtask/src/codegen.rs`][ra-codegen] has a `check: bool` flag.
   - CI runs `cargo codegen --check` in its "Codegen checks" step.
   - No `*.rs` file at that commit names `sourcegen`.
2. `unicode-ident` writes `src/tables.rs` with a separate `generate/` crate ([`write.rs`][unicode-ident-write]).
   - CI regenerates the file and runs `git diff --exit-code`.
   - The header reads `// @generated by ../generate. To regenerate, run ...`.
3. `syn` has a `codegen/` crate, `syn-internal-codegen`, with `publish = false` and a workspace of its own ([`file.rs`][syn-codegen]).
   CI runs `cargo run --manifest-path codegen/Cargo.toml`, then `git diff --exit-code`.
4. `regex-syntax` commits tables that `ucd-generate` writes, through `regex-cli generate unicode` ([table header][regex-age], [`regex-cli` README][regex-cli]).
   The headers read `DO NOT EDIT THIS FILE. IT WAS AUTOMATICALLY GENERATED BY: ucd-generate ...`.
5. ICU4X commits baked data under `provider/data/*` ([exporter][icu4x-export]).
   - The files open with `// @generated`, and a `fingerprints.csv` sits beside them.
   - Its CI job `full-datagen` holds the comment "Generated Rust is not stable across Rust versions".
6. `windows-rs` runs a `gen.yml` workflow that regenerates and runs `git diff --exit-code`.
   Its error text says to run the generator and commit.
7. matklad's ["Self Modifying Code"][self-modifying] (2022-03-26) argues for plain text-in, text-out generation.
   - A `#[test]` rewrites marked regions of a source file, only when the content changed.
   - He writes that "writable src/ is required only during development".
   - He calls the macro alternatives "arguably even more opaque".
8. The [Cargo book][cargo-build-scripts] says a build script should not change files outside `OUT_DIR`.
   Its code generation example uses `include!(concat!(env!("OUT_DIR"), ...))`.

## How the code is written

1. rust-analyzer's `xtask` uses `proc_macro2` and `quote` ([`codegen.rs`][ra-codegen]).
   - A `reformat()` pipes the text into a pinned-toolchain `rustfmt --config-path rustfmt.toml`.
   - The preamble reads `//! Generated by \`cargo xtask codegen grammar\`, do not edit by hand.`
2. `syn`'s codegen builds a `TokenStream` with `quote`, parses it into a `syn::File` with `syn::parse2`, and prints it with `prettyplease::unparse` ([`file.rs`][syn-codegen]).
   It prepends `// This file is @generated by syn-internal-codegen.` and skips the write when the bytes are unchanged.
3. `prost-build` has a `format` feature, `dep:prettyplease` and `dep:syn`, that runs `syn::parse_file` and `prettyplease::unparse` ([`config.rs`][prost-format]).
   It prepends `// This file is @generated by prost-build.`
4. `windows-bindgen` builds tokens with `proc-macro2` and `quote` ([`format.rs`][windows-format]).
   It pipes the text to `rustfmt` and returns the tokens unformatted when that fails.
5. ICU4X's baked exporter has `pretty: bool`, which runs `rustfmt` ([exporter][icu4x-export]).
   Without it the output stays as token text inside `macro_rules!` bodies, which rustfmt does not reformat.
6. `phf_codegen` returns `Display` types such as `DisplayMap`, with no formatter ([`lib.rs`][phf-codegen]).
7. `databake`'s `Bake` trait produces a `proc_macro2::TokenStream`.
   Its README shows unformatted tokens, and it depends on `proc-macro2` and `quote`.
8. `genco` is a quasiquoter that tracks whitespace ([`Cargo.toml`][genco]).
   It depends on `genco-macros`, `relative-path` and `smallvec`.
9. `unicode-ident`'s writer uses `writeln!`, with 16 bytes per line ([`write.rs`][unicode-ident-write]).
   `ucd-generate` uses a `LineWriter` with `columns: 79` ([`writer.rs`][ucd-writer]).
   Neither uses a token library.

## Long lines and arrays

1. prettyplease's README says rustfmt "gave up formatting" a generated line of over 1,000 characters.
   It claims about 95% of rustfmt's quality.
2. prettyplease fills lines only for arrays of byte, char, int and bool literals (`simple_array` in [`expr.rs`][prettyplease-array]).
   Arrays of strings, floats or other expressions get one element per line.
3. rustfmt's `array_width` defaults to 60, and `error_on_line_overflow` is unstable and off ([configuration][rustfmt-config], read on `main` on 2026-11-10).
4. rustfmt's `format_generated_files` is unstable and defaults to `true`.
   A file is generated when one of its first lines holds `@generated`; `generated_marker_line_search_limit` defaults to 5.

## Conventions

| Project | Header | Formatting escape | Where it lands |
|:--|:--|:--|:--|
| `unicode-ident` | `// @generated by ../generate`, with the commands | `#[rustfmt::skip] mod tables;` in `lib.rs` | committed `src/` |
| `regex-syntax` | `DO NOT EDIT ... ucd-generate <args>` and the Unicode version | none on `mod unicode_tables`; the output wraps at 79 | committed `src/` |
| `syn` | `@generated by syn-internal-codegen` | prettyplease output, and `#![allow(...)]` in the file | committed `src/gen/` |
| rust-analyzer | `//! Generated by cargo xtask codegen <type>, do not edit by hand.` | `#![allow(bad_style, missing_docs, unreachable_pub)]` in the file | committed `src/` |
| `prost-build` | `// This file is @generated by prost-build.` | none | `OUT_DIR` for callers, committed in `prost-types` |
| ICU4X | `// @generated` | tables inside macros | committed `provider/data/*`, or `include!` |

- `ucd-generate` and ICU4X walk `BTreeMap` and `BTreeSet`, so their output is the same on every run.
- `syn` and `unicode-ident` skip the write when the bytes are unchanged.
- `unicode-ident` records the Unicode version in the header and in a `UNICODE_VERSION` constant.

## Dependency cost

Counts come from each `Cargo.toml` and from crates.io on 2026-11-10.

| Option | Crates added |
|:--|:--|
| `quote` | 3: `quote` 1.0.47, `proc-macro2` 1.0.107, `unicode-ident` |
| `quote` and `prettyplease` | 5: the three above, `prettyplease` 0.3.0 and `syn` 3.0.10 |
| `genco` | 5, 3 of them direct |
| `databake` | 3, with `quote` and `proc-macro2` |
| a `String` writer | 0 |

`syn` 3.0.10 was published on 2026-11-09, and `prettyplease` 0.3.0 requires it.
A project on `syn` 2 then carries both versions.

## Not verified

- Build times: nothing was built.
- Crate counts: crates.io returned no dependency names, so they were read from each `Cargo.toml`.
- prettyplease's layout of a large keyword table: not run.
- Whether rustfmt gives up on large `match` arms, beyond prettyplease's README citing rustfmt#3697.
- The history of rust-analyzer's move from `sourcegen` to `xtask`.
- `genco-macros`' own dependencies.
- Whether `regex` and `windows-rs` CI diff the committed files on every pull request.
  `unicode-ident`, `syn`, `windows-rs` and rust-analyzer do.
