L Controls retry behavior. Each field is documented individually below.
T 69 text.html.markdown
L 
L If `retry` is a number, it will be used as `limit` and other defaults will remain in place.
T 91 text.html.markdown
L 
L `retry.limit`, including numeric shorthand, must be a finite, non-negative integer.
T 83 text.html.markdown
L 
L Network errors (e.g., DNS failures, connection refused, offline) are automatically retried for retriable methods. Only errors recognized as network errors are retried; other errors (e.g., programming bugs) are thrown immediately. Use `shouldRetry` to customize this behavior.
T 275 text.html.markdown
L 
L A hook can change `retry.limit` through `options`. Ky reads the limit again when each attempt starts. A `beforeRequest` or `beforeRetry` hook runs before the attempt starts, so it can lower or raise the limit. An `afterResponse` hook runs after the attempt started, so it can lower the limit, for example to stop retrying once a response says so. A higher limit set there only applies from the next attempt.
T 407 text.html.markdown
L 
L `413 Payload Too Large` is only retried when the response includes a retry timing header, unless `shouldRetry` returns `true`.
T 126 text.html.markdown
L 
L When the response status is contained in `afterStatusCodes` and the retry is allowed by `statusCodes` or `shouldRetry`, Ky uses retry timing headers to choose the retry delay. [`Retry-After`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Retry-After) may provide a delay in seconds or an HTTP-date. If `Retry-After` is missing, Ky falls back to rate-limit timing headers (`RateLimit-Reset`, `X-RateLimit-Retry-After`, `X-RateLimit-Reset`, and `X-Rate-Limit-Reset`). Numeric `Retry-After` and `X-RateLimit-Retry-After` values are interpreted as delay seconds. Numeric `RateLimit-Reset`, `X-RateLimit-Reset`, and `X-Rate-Limit-Reset` values may also be interpreted as Unix timestamps, from 2001-09-09 onwards. A value below that is read as delay seconds, and a timestamp already in the past means the retry happens immediately. If the status code is not in `afterStatusCodes`, retry timing headers will be ignored.
T 924 text.html.markdown

T 107 text.html.markdown
L

T 127 text.html.markdown
L To clamp the delay, set `backoffLimit` to 1000, for example.
T 60 text.html.markdown
L A delay from a retry timing header is not subject to this limit; use `maxRetryAfter` to bound it.
T 97 text.html.markdown
L By default, the delay is calculated with `0.3 * (2 ** (attemptCount - 1)) * 1000`. The delay increases exponentially.
T 117 text.html.markdown
L

T 132 text.html.markdown

T 313 text.html.markdown

T 240 text.html.markdown

L **Note:** This is different from the `beforeRetry` hook:
T 56 text.html.markdown

T 85 text.html.markdown

T 84 text.html.markdown

T 104 text.html.markdown
L - `false` to prevent a retry (no retry will occur)
T 50 text.html.markdown

T 149 text.html.markdown

L #### What's the difference between `baseUrl` and `prefix`?
T 58 text.html.markdown
L 
L **`baseUrl`** follows standard URL resolution rules — the same behavior as `new URL(input, baseUrl)`. A leading slash on the input means origin-root, overriding any path in the base URL.
T 188 text.html.markdown
L 
L **`prefix`** does plain string joining before URL resolution. The leading slash on the input is stripped, so it always appends to the prefix regardless.
T 152 text.html.markdown
