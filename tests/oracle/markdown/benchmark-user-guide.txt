L #### `--benchmark_dry_run` (BENCHMARK_DRY_RUN)
T 46 text.html.markdown
L 
L If enabled, forces each benchmark to execute exactly one iteration and one repetition, bypassing any configured `MinTime()`, `MinWarmUpTime()`, `Iterations()`, or `Repetitions()`. This is useful for quickly verifying that benchmarks can run successfully without waiting for full execution.
T 289 text.html.markdown
L 
L **Example:**
T 12 text.html.markdown
L ```bash
T 7 text.html.markdown
L $ ./benchmark --benchmark_dry_run
T 33 text.html.markdown
L ```
T 3 text.html.markdown

L ## Runtime and Reporting Considerations
T 39 text.html.markdown
L 
L When the benchmark binary is executed, each benchmark function is run serially.
T 79 text.html.markdown
L The number of iterations to run is determined dynamically by running the
T 72 text.html.markdown
L benchmark a few times and measuring the time taken and ensuring that the
T 72 text.html.markdown
L ultimate result will be statistically stable. As such, faster benchmark
T 71 text.html.markdown
L functions will be run for more iterations than slower benchmark functions, and
T 78 text.html.markdown
L the number of iterations is thus reported.
T 42 text.html.markdown
L 
L In all cases, the number of iterations for which the benchmark is run is
T 72 text.html.markdown
L governed by the amount of time the benchmark takes. Concretely, the number of
T 77 text.html.markdown
L iterations is at least one, not more than 1e9, until CPU time is greater than
T 77 text.html.markdown
L the minimum time, or the wallclock time is 5x minimum time. The minimum time is
T 79 text.html.markdown
L set per benchmark by calling `MinTime` on the registered benchmark object.
T 74 text.html.markdown
L

T 60 text.html.markdown
L `--benchmark_min_time=<value>` command-line option. This flag supports two
T 22 text.html.markdown

T 28 text.html.markdown meta.tag.other.unrecognized.html.derivative entity.name.tag.html
T 29 text.html.markdown meta.tag.other.unrecognized.html.derivative punctuation.definition.tag.end.html
T 74 text.html.markdown
L forms:
T 6 text.html.markdown
L 
L * `--benchmark_min_time=<float>s` sets the minimum running time for each
T 24 text.html.markdown
T 25 text.html.markdown meta.tag.other.unrecognized.html.derivative punctuation.definition.tag.begin.html
T 30 text.html.markdown meta.tag.other.unrecognized.html.derivative entity.name.tag.html
T 31 text.html.markdown meta.tag.other.unrecognized.html.derivative punctuation.definition.tag.end.html
T 72 text.html.markdown

T 34 text.html.markdown
L * `--benchmark_min_time=<integer>x` runs each benchmark repetition for an
T 24 text.html.markdown
T 25 text.html.markdown meta.tag.other.unrecognized.html.derivative punctuation.definition.tag.begin.html
T 32 text.html.markdown meta.tag.other.unrecognized.html.derivative entity.name.tag.html
T 33 text.html.markdown meta.tag.other.unrecognized.html.derivative punctuation.definition.tag.end.html
T 73 text.html.markdown

T 38 text.html.markdown

T 61 text.html.markdown

T 42 text.html.markdown

T 24 text.html.markdown

T 71 text.html.markdown

T 43 text.html.markdown

T 84 text.html.markdown
L of benchmark and report the error. Note that only future iterations of the
T 74 text.html.markdown
L `KeepRunning()` are skipped. For the ranged-for version of the benchmark loop
T 77 text.html.markdown
L Users must explicitly exit the loop, otherwise all iterations will be performed.
T 80 text.html.markdown
L Users may explicitly return to exit the benchmark immediately.
T 62 text.html.markdown

T 80 text.html.markdown

T 80 text.html.markdown

L ## A Faster KeepRunning Loop
T 28 text.html.markdown
L 
L A ranged-based for loop should be used in preference to
T 55 text.html.markdown
L the `KeepRunning` loop for running the benchmarks. For example:
T 63 text.html.markdown
L 
L ```c++
T 6 text.html.markdown
L static void BM_Fast(benchmark::State &state) {
T 46 text.html.markdown
L   for (auto _ : state) {
T 24 text.html.markdown
L     FastOperation();
T 20 text.html.markdown
L   }
T 3 text.html.markdown
L }
T 1 text.html.markdown
L BENCHMARK(BM_Fast);
T 19 text.html.markdown
L ```
T 3 text.html.markdown
L 
L The reason the ranged-for loop is faster than using `KeepRunning`, is
T 69 text.html.markdown
L because `KeepRunning` requires a memory load and store of the iteration count
T 77 text.html.markdown
L ever iteration, whereas the ranged-for variant is able to keep the iteration count
T 82 text.html.markdown
L in a register.
T 14 text.html.markdown
L 
L For example, an empty inner loop of using the ranged-based for method looks like:
T 81 text.html.markdown
L 
L ```asm
T 6 text.html.markdown
L # Loop Init
T 11 text.html.markdown
L   mov rbx, qword ptr [r14 + 104]
T 32 text.html.markdown
L   call benchmark::State::StartKeepRunning()
T 43 text.html.markdown
L   test rbx, rbx
T 15 text.html.markdown
L   je .LoopEnd
T 13 text.html.markdown
L .LoopHeader: # =>This Inner Loop Header: Depth=1
T 48 text.html.markdown
L   add rbx, -1
T 13 text.html.markdown
L   jne .LoopHeader
T 17 text.html.markdown
L .LoopEnd:
T 9 text.html.markdown
L ```
T 3 text.html.markdown
L 
L Compared to an empty `KeepRunning` loop, which looks like:
T 58 text.html.markdown
L 
L ```asm
T 6 text.html.markdown
L .LoopHeader: # in Loop: Header=BB0_3 Depth=1
T 44 text.html.markdown
L   cmp byte ptr [rbx], 1
T 23 text.html.markdown
L   jne .LoopInit
T 15 text.html.markdown
L .LoopBody: # =>This Inner Loop Header: Depth=1
T 46 text.html.markdown
L   mov rax, qword ptr [rbx + 8]
T 30 text.html.markdown
L   lea rcx, [rax + 1]
T 20 text.html.markdown
L   mov qword ptr [rbx + 8], rcx
T 30 text.html.markdown
L   cmp rax, qword ptr [rbx + 104]
T 32 text.html.markdown
L   jb .LoopHeader
T 16 text.html.markdown
L   jmp .LoopEnd
T 14 text.html.markdown
L .LoopInit:
T 10 text.html.markdown
L   mov rdi, rbx
T 14 text.html.markdown
L   call benchmark::State::StartKeepRunning()
T 43 text.html.markdown
L   jmp .LoopBody
T 15 text.html.markdown
L .LoopEnd:
T 9 text.html.markdown
L ```
T 3 text.html.markdown
L 
L Unless C++03 compatibility is required, the ranged-for variant of writing
T 73 text.html.markdown
L the benchmark loop should be preferred.
