L ### Version Categories
T 22 text.html.markdown
L 
L Every version of node belongs to exactly one of these categories:
T 65 text.html.markdown
L 
L   - `alpha`: an Alpha prerelease, like `v27.0.0-alpha.1.0.0`, which precedes a major's first release
T 100 text.html.markdown
L   - `lts`: a version marked as LTS in the mirror's `index.tab`
T 62 text.html.markdown
L   - `non-lts`: any other version of node
T 40 text.html.markdown
L   - `iojs`: any version of io.js, from the io.js mirror
T 55 text.html.markdown
L 
L By default, `nvm` selects versions from every category except `alpha`, so `nvm install node`, `nvm install 27`, and `nvm ls-remote` never pick or show an Alpha. Every command that selects or lists versions accepts `--only=` with a comma-separated list of categories to select from instead; Alphas, even an exact version, are only selected when `alpha` is included:
T 364 text.html.markdown
L 
L ```sh
T 5 text.html.markdown
L nvm ls-remote --only=alpha
T 26 text.html.markdown
L nvm install --only=alpha 27
T 27 text.html.markdown
L nvm use --only=alpha,lts,non-lts 27.0.0-alpha.1.0.0
T 51 text.html.markdown
L ```
T 3 text.html.markdown
L 
L To change the default, set `NVM_ONLY` to the same kind of list, for example in your shell profile; `--only=` overrides it. An LTS selection (`--lts`, `--lts=<name>`, or an `lts/` version) picks versions through the matching `lts/` alias, so it only picks LTS versions, and it can't be combined with an `--only=` that excludes `lts`.

T 332 text.html.markdown
L 
L An alias can store `--only=` too, so `nvm alias default --only=alpha node` makes the latest installed version of node, including Alphas, the default.

L ## Environment variables
T 24 text.html.markdown

T 48 text.html.markdown

L ## Installing nvm on Alpine Linux
T 33 text.html.markdown
L 
L In order to provide the best performance (and other optimizations), nvm will download and install pre-compiled binaries for Node (and npm) when you run `nvm install X`. The Node project compiles, tests and hosts/provides these pre-compiled binaries which are built for mainstream/traditional Linux distributions (such as Debian, Ubuntu, [CentOS](https://www.centos.org), [RedHat](https://www.redhat.com) et al).
T 411 text.html.markdown
L 
L [Alpine Linux](https://www.alpinelinux.org), unlike mainstream/traditional Linux distributions, is based on [BusyBox](https://www.busybox.net/), a very compact (~5MB) Linux distribution. BusyBox (and thus Alpine Linux) uses a different C/C++ stack to most mainstream/traditional Linux distributions - [musl](https://www.musl-libc.org/). This makes binary programs built for such mainstream/traditional distributions incompatible with Alpine Linux, so on `x64` and `arm64` nvm requests a `musl` build instead. nodejs.org publishes those only for some recent `x64` releases, so for anything else the download 404s and `nvm install X` falls back to compiling from source, unless you point it at a mirror that has one (see [Platforms without official binaries](#platforms-without-official-binaries)).
T 796 text.html.markdown
L 
L There is a `-s` flag for `nvm install` which requests nvm download Node source and compile it locally.
T 102 text.html.markdown
L 
L If installing nvm on Alpine Linux *is* still what you want or need to do, you should be able to achieve this by running the following from your Alpine Linux shell, depending on which version you are using:

L **Macs with Apple Silicon chips**
T 33 text.html.markdown
L 
L Experimental support for the Apple Silicon chip architecture was added in node.js v15.3 and full support was added in v16.0.
T 124 text.html.markdown
L Because of this, if you try to install older versions of node as usual, you will probably experience either compilation errors when installing node or out-of-memory errors while running your code.
T 196 text.html.markdown
L 
L So, if you want to run a version prior to v16.0 on an Apple Silicon Mac, it may be best to compile node targeting the `x86_64` Intel architecture so that [Rosetta 2](https://support.apple.com/en-us/HT211861) can translate the `x86_64` processor instructions to ARM-based Apple Silicon instructions.
T 298 text.html.markdown
L Here's what you will need to do:
T 32 text.html.markdown
L 
L - Install Rosetta, if you haven't already done so
T 49 text.html.markdown
L 
L   ```sh
T 7 text.html.markdown
L   $ softwareupdate --install-rosetta
T 36 text.html.markdown
L   ```
T 5 text.html.markdown
L 
L   You might wonder, "how will my Apple Silicon Mac know to use Rosetta for a version of node compiled for an Intel chip?".
T 122 text.html.markdown
L   If an executable contains only Intel instructions, macOS will automatically use Rosetta to translate the instructions.
T 120 text.html.markdown
L 
L - Open a shell that's running using Rosetta
T 43 text.html.markdown
L 
L   ```sh
T 7 text.html.markdown
L   $ arch -x86_64 zsh
T 20 text.html.markdown
L   ```
T 5 text.html.markdown
L 
L   Note: This same thing can also be accomplished by finding the Terminal or [iTerm](https://iterm2.com) App in Finder, right clicking, selecting "Get Info", and then checking the box labeled "Open using Rosetta".
T 212 text.html.markdown
L 
L   Note: This terminal session is now running in `zsh`.
T 54 text.html.markdown
L   If `zsh` is not the shell you typically use, `nvm` may not be `source`'d automatically like it probably is for your usual shell through your dotfiles.
T 152 text.html.markdown
L   If that's the case, make sure to source `nvm`.
T 48 text.html.markdown
L 
L   ```sh
T 7 text.html.markdown
L   $ source "${NVM_DIR}/nvm.sh"
T 30 text.html.markdown
L   ```
T 5 text.html.markdown
L 
L - Install whatever older version of node you are interested in. Let's use 12.22.1 as an example.
T 96 text.html.markdown
L   This will fetch the node source code and compile it, which will take several minutes.
T 87 text.html.markdown
L 
L   ```sh
T 7 text.html.markdown
L   $ nvm install v12.22.1 --shared-zlib
T 38 text.html.markdown
L   ```
T 5 text.html.markdown
L 
L   Note: You're probably curious why `--shared-zlib` is included.
T 64 text.html.markdown
L   There's a bug in recent versions of Apple's system [`clang`](https://clang.llvm.org/) compiler.
T 97 text.html.markdown
L   If one of these broken versions is installed on your system, the above step will likely still succeed even if you didn't include the `--shared-zlib` flag.
T 156 text.html.markdown
L   However, later, when you attempt to `npm install` something using your old version of node.js, you will see `incorrect data check` errors.
T 140 text.html.markdown
L   If you want to avoid the possible hassle of dealing with this, include that flag.
T 83 text.html.markdown
L   For more details, see [this issue](https://github.com/nodejs/node/issues/39313) and [this comment](https://github.com/nodejs/node/issues/39313#issuecomment-902395576)
T 168 text.html.markdown
L 
L - Exit back to your native shell.
T 33 text.html.markdown
L 
L   ```sh
T 7 text.html.markdown
L   $ exit
T 8 text.html.markdown
L   $ arch
T 8 text.html.markdown
L   arm64
T 7 text.html.markdown
L   ```
T 5 text.html.markdown
L

T 142 text.html.markdown

T 84 text.html.markdown

T 120 text.html.markdown

T 7 text.html.markdown
L   $ node -p process.arch
T 24 text.html.markdown

T 5 text.html.markdown
L   ```
