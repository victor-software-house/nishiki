# oracle

Rules for the Shiki oracle, beside the root guide's invariants.
[README.md](README.md) lists the scripts.

1. `mise run oracle` runs Shiki on every input in [`inputs.ts`](inputs.ts) and writes its scopes to `tests/oracle/<language>/`.
   `ORACLE_LANG=<language>` writes one language only.
2. A new language adds its inputs and fixtures.
   [`tests/oracle/SOURCES.md`](../tests/oracle/SOURCES.md) records each input's source and licence, read at the source.
3. An input is pinned to a commit.
   Held-out inputs stay unseen until the development inputs pass.
4. A generated table is regenerated by its script, never edited by hand.
   Where a workflow checks a table against its script, the check runs on every pull request that touches either.
5. Three tools reach past the fixtures, each run by hand with an ignored test:
   - `fuzz.ts` writes mutated and generated documents, bare and in Markdown fences;
   - `dump.ts` writes held-out files;
   - `onig.ts` checks a language's hand matchers against Oniguruma, through the language's `matchers_answer_the_probe_cases` test.

   `the_corpus_matches_shiki` in `tests/it/oracle.rs` compares a corpus with nishiki.
   `fuzz/<language>.ts` holds what the tools draw on for one language.
6. `mise run oracle:coverage` writes `tests/oracle/COVERAGE.md`: how much of each hand-lexed grammar the fixtures exercise, and every unit they do not.
   - A pull request that changes the oracle's inputs or fixtures writes it again.
   - `coverage-waivers.ts` waives the units no document can reach, each with a reason, and lists the grammars that are complete.
   - The Oracle coverage workflow (`.github/workflows/coverage.yml`) runs `mise run check:oracle-coverage`.
     It fails on a stale report, a wrong waiver, or a gap in a complete grammar.
   - A new hand lexer adds its grammar to `handLexed` in `coverage.ts`; the run fails on a loaded grammar it cannot place.
   - A gap closes with an input: a pinned, licensed third-party file first, then one written for nishiki under `inputs/`.
   - `bun run oracle/coverage.ts --pick <grammar> <lang> <file or directory>…` ranks candidate files by the units each adds beyond the fixtures, and prints the units still left.
   - A written input is a text import in `inputs.ts`, listed as `{ lang, name, text }`.
   - An input may hold text that is not valid in its language, in a commented section, to reach a grammar unit, because fidelity covers text being edited.
     A waiver is only for a unit no document can reach.
7. Scripts are TypeScript run by Bun, with each import pinned to an exact version, such as `shiki@4.6.0`.
8. [`grammars.ts`](grammars.ts) makes one edit to Shiki's grammars, and no other.
   - In C++'s `string_context`, a rule whose patterns include only grammars the oracle leaves out keeps its match with no patterns inside.
   - vscode-textmate skips such a rule, so without the edit `R"re(` and `R"glsl(` would read as other raw strings, which full Shiki does not do.
   - nishiki lexes them with their own rules and plain text inside.
